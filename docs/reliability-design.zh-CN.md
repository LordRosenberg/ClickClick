# ClickClick 技术概览：面向复杂移动任务的 Agent Harness

[首页](../README.zh-CN.md) · [English](reliability-design.md) · [模块架构](architecture.zh-CN.md) · [设计取舍](design-decisions.zh-CN.md)

## 摘要

ClickClick 将通用多模态模型接入 Android 设备，通过可修订阶段规划、持久任务记忆、应用技能和带反馈的设备执行完成复杂工作流。系统将模型的语义决策与运行时的机械校验分离：模型决定要完成什么、如何应对页面变化；Harness 维护上下文、技能作用域、动作绑定和执行记录。系统在 AndroidWorld 的 116 个任务实例中通过 115 个，成功率为 99.14%。[评测协议与结果](androidworld-results-20260921.md)给出实验条件。

## 1. 问题与设计目标

移动工作流需要在不断变化的界面中保持目标、数据和操作对象的一致性。一个食谱转录任务可能同时涉及读取长笔记、跨应用导航、填写多个表单和保存后核验。即使单步点击正确，源字段遗失、旧画面、重复记录或未完成范围仍可能导致任务失败。

ClickClick 围绕四个目标组织运行时：随新证据修订计划；跨阶段保存可回查的信息；将应用知识用于当前任务；把动作结果反馈给后续决策。可观测性贯穿这些模块，使开发者能从结果回溯到具体模型输入与设备操作。

## 2. 可修订的阶段规划

Planner 每次确定一个当前阶段，用结果描述目标，并维护后续阶段的暂定路线。Executor 在当前阶段内选择具体操作。页面与预期不符时，Executor 可以请求重规划；阶段完成后，控制权回到 Planner，由其根据新状态决定下一阶段。

这种分工保留了局部执行的灵活性，也避免未来计划提前成为不可变要求。原始指令始终是任务依据：新增与更新、源字段、目标数量、操作顺序和保留条件不会因为中间计划的简化而被替换。

默认循环使用 Planner 与 Executor。需要独立判断证据冲突或任务要求时，任一角色可请求 Reviewer；也可配置强制最终审核。角色转换与预算检查由运行时实现，语义判断仍由模型完成。[角色协议](../shared/revisable.py)与[编排器](../agent/revisable/orchestrator.py)定义这一流程。

## 3. 持久记忆与长任务连续性

Session 在当前模型上下文之外保存观察、动作事件、阶段、对话原文及版本化笔记。Harness 为每次调用选择相关内容，并提供来源读取工具。模型可根据明确的信息缺口回查历史文字或截图，而无需重复执行已经完成的页面操作。

历史压缩以完整执行步骤为边界，保留最近步骤。来源记录与未解决问题独立保存，继续执行时恢复。压缩后的摘要用于减少上下文负担，原始证据仍可检索。历史截图承担事实核对，当前观测承担动作定位，两者拥有不同用途。

对于长列表，任务状态还包括已经处理的记录、待处理行和搜索范围。共享遍历技能根据可见锚点调整滚动：清晰列表允许较大步幅，同名或边界模糊的记录需要保留游标、小幅揭示并逐行处理。停止条件取决于任务是查找一个目标、处理一组记录还是覆盖整个集合。这是长任务执行中的一种具体策略，而不是额外的独立 Agent 架构。

实现入口：[持久记录](../agent/revisable/store.py)、[来源检索](../agent/revisable/recall.py)、[上下文压缩](../agent/revisable/dialogue.py)、[列表遍历技能](../skills/generic/adaptive-list-traversal/SKILL.md)。

## 4. 应用技能与受限复合动作

技能采用分层内容：应用 core 描述稳定的应用约定，workflow 描述具体任务流程，generic skill 提供跨应用方法。Planner 选择当前阶段所需技能，运行时依据设备 profile、目标应用、前台应用与角色投射内容，并记录交付的 ID、版本和内容哈希。

技能还可以声明受支持的复合动作。例如，检查详情后返回列表需要保留详情页证据，同时重新建立返回后的操作依据。Harness 将其实现为闭集原语：执行各个子动作，保留中间观测和回执，再提供最新可操作状态。当前阶段、激活技能和实际前台应用共同限定其使用范围。

这种接口将应用知识与执行能力连接起来，同时限制模型能够生成的动作组合。复合动作不是任意脚本接口；一次提交可以包含多次物理输入，两种计数分别保存。技能的编写、角色内容和候选更新审核见[技能指南](../skills/README.zh-CN.md)。

## 5. 观测绑定的设备执行

观察由 scrcpy 画面、Accessibility Collector 的结构与事件组成；ADB 提供画面回退。采集使用请求边界与窗口状态检查，并在限定时间内重采。角色交接后刷新观察，减少将旧页面交给下一角色的机会。

Executor 的动作必须引用当前 observation ID。对于支持的本地原生点击，Harness 保留所观察节点的句柄，执行前刷新并检查节点身份，再调用一次 Android `ACTION_CLICK`。节点失效或结果不确定时返回反馈，不自动点击旧坐标。坐标动作仍用于图像控件及不支持原生绑定的路径。

文本输入提供另一类检查：对可识别的可编辑字段执行聚焦、替换和读回，报告实际发生的步骤。输入成功与保存成功分别判断，后续观察用于确认应用中的结果。[动作与观测事务](../agent/action_observation.py)、[输入控制](../agent/targeted_input.py)和[原生节点实现](../android/accessibility-collector/app/src/main/java/ai/clickclick/collector/NodeClickStore.kt)给出具体实现。

## 6. 可观测性与评测

Console 将任务、角色调用、模型输入输出、技能、工具、动作回执和观察关联展示。开发者可在同一工作区查看实时设备与历史步骤，检查计划变化、输入错误及采集降级，并分析调用耗时与用量。[可观测性指南](observability.zh-CN.md)介绍使用方法。

评测器独立于 Agent Harness。AndroidWorld 初始化任务并检查最终状态；运行时记录执行和资源消耗。115/116 是模型、运行时、技能、工具与环境共同作用的系统结果，不是某一机制的单独增益。实验条件、选择规则和动作空间见[评测报告](androidworld-results-20260921.md)。[演示视频](demos.md)展示具体工作流。

## 7. 适用范围

ClickClick 适合需要跨应用信息传递、多字段录入、记录管理和可追查执行过程的 Android 工作流。持久记录提供回查能力，但不能保证模型摘要完整；原生节点绑定校验机械身份，但不能判断全部业务语义；遍历技能显式管理范围，但不构成形式化覆盖证明。应用结果仍需要结合页面或外部评测检查。

系统的贡献在于这些机制的协同和可用实现。
