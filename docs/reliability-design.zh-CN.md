# 技术概览

[首页](../README.zh-CN.md) · [English](reliability-design.md) · [架构详解](architecture.zh-CN.md)

ClickClick 让多模态模型通过屏幕完成 Android 工作流。本文介绍**任务中的主要难点、核心设计及其作用**；模块接口与运行流程见[架构详解](architecture.zh-CN.md)。

## 为什么需要 Agent Harness

跨应用任务不只是连续点击。以转录食谱为例：模型需要记住来源字段、理解目标应用、填写多条记录，并判断哪些已经保存。页面变化或一次输入失败，都可能改变后续操作。

Agent Harness 为模型提供持续执行所需的上下文、工具和反馈。**模型决定任务含义与操作路径，运行时负责记录、校验和执行。**

## 四个核心机制

| 任务难点 | 设计 | 作用 |
| --- | --- | --- |
| 执行前无法预知每个页面 | 可修订的阶段规划 | 明确当前目标，根据新观察调整后续路线 |
| 跨页面、跨应用容易丢失细节 | 独立笔记、结构化摘要与来源回查 | 保留重要数据，控制上下文大小，缺失时回读 |
| 应用有不直观但可复用的操作规则 | 按应用和设备范围加载技能 | 复用已知经验，减少重复探索 |
| 动作发出不代表应用已完成操作 | 当前观测绑定与执行反馈 | 检查目标和输入，把实际结果带入下一次决策 |

这些机制共同支持一个循环：**确定阶段 → 操作与观察 → 更新记忆 → 继续或调整计划**。需要独立判断时，Planner 或 Executor 可以请求 Reviewer。

## 在跨应用任务中如何协作

| 阶段 | 模型处理的问题 | 系统提供的支持 |
| --- | --- | --- |
| 读取来源 | 哪些字段之后还要用？ | 笔记保存数据，来源记录支持回查 |
| 进入目标应用 | 当前页面应该怎样操作？ | 当前观测与适用技能 |
| 逐条录入 | 本次输入是否生效，哪些记录已完成？ | 动作回执、输入读回与任务进度 |
| 完成交付 | 结果是否满足原始要求？ | 保存后的观察；必要时独立审核 |

## 结果可检查，能力有边界

Console 将模型输入、决策、动作和观察串起来，便于理解结果及定位问题。基准评测器独立检查任务最终状态，具体条件见[评测报告](androidworld-results-20260921.md)。

来源可追溯不等于模型理解一定正确，输入成功不等于记录已保存，技能也不能覆盖所有应用版本。系统保留证据和反馈，让后续判断有据可查。
