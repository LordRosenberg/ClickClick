# 技术概览

[首页](../README.zh-CN.md) · [English](reliability-design.md) · [架构详解](architecture.zh-CN.md)

ClickClick 让多模态模型通过屏幕完成 Android 工作流。本文分别介绍**核心能力、关键设计难点与取舍、工程支撑和效果评价**；模块接口与运行流程见[架构详解](architecture.zh-CN.md)。

## 为什么需要 Agent Harness

跨应用任务不只是连续点击。以转录食谱为例：模型需要记住来源字段、理解目标应用、填写多条记录，并判断哪些已经保存。页面变化或一次输入失败，都可能改变后续操作。

Agent Harness 为模型提供持续执行所需的上下文、工具和反馈。**模型决定任务含义与操作路径，运行时负责记录、校验和执行。**

## 关键设计难点与取舍

### 上下文压缩与事实保真

**难点：** 长任务的历史持续增长，全量回传会增加开销，直接删减又可能丢失跨应用所需字段、失败记录或来源；摘要还可能引入原文没有的结论。

**设计：** 原始记录、版本笔记和结构化摘要分层保存。压缩较早历史，保留最近两个完整步骤；当前计划、笔记和预算分别进入角色上下文，摘要条目绑定来源，缺少细节时回查原文。

**取舍：** 压缩减少每轮输入，但回查和校验需要额外开销。来源可追溯不保证模型理解正确；可选 Jev 校验也有成本与降级边界，不能据此保证摘要无误。详见[记忆与上下文](memory-and-context.zh-CN.md)。

### 异步观测与动作目标一致性

**难点：** 截图、无障碍树和实际界面来自不同时间点。页面切换或内容更新后，旧索引、坐标和焦点可能已经指向其他对象。

**设计：** 通过采集请求／动作帧边界更新画面，按窗口代次检查图树并有界重采；观测 ID 绑定索引和坐标变换。支持的点击由 Collector 保留节点、刷新并复核属性后执行；定向输入核对字段与焦点，再写入和读回。

**取舍：** 重采次数有界，避免动态页面一直等不到稳定状态；结构缺失时仍可提供可用画面。异步来源无法构成严格的原子快照，输入读回也不单独证明应用已经保存。详见[观测与执行一致性详设](observation-execution-consistency.zh-CN.md)。

### 在线介入与在途执行的并发

**难点：** 用户修改可能在模型等待或动作执行期间到达。只改计划文本，无法阻止旧响应继续派发动作；重建整个任务又会丢失仍有效的上下文与累计消耗。

**设计：** 用户修改先进入持久化、有序控制收件箱，由 Planner 判断保留阶段还是重规划。指令版本与执行代次使过时调用失去提交资格；提问则保存未完成的角色会话，回答后续接同一调用，并在 GUI 动作前刷新观测。

**取舍：** 接收修改与计划生效分别记录。已派发动作先保存真实结果，不自动撤销外部效果；有效阶段和 Executor 历史可继续使用。暂停保持暂停，完成后的修改创建关联后续任务，预算与历史记录不重置。详见[双向 HITL 与在线重规划](hitl-design.zh-CN.md)。

### 数据库提交与手机副作用之间的恢复

**难点：** 数据库事务不能覆盖 ADB 操作。崩溃可能发生在手机已执行、回执尚未保存的间隙，此时既不能断言未执行，也不能安全地直接重试。

**设计：** 按“派发前意图 → Driver 执行 → 原始回执 → 后观测 → 步骤与完整状态”分阶段持久化。Driver journal 按 operation ID 去重，任务所有权、执行代次与设备输入隔离限制旧 worker；恢复清单保留原角色、计划、笔记、对话和已加载技能。

**取舍：** 这些机制保证受控范围内的去重与状态一致性，不提供手机业务效果的 exactly-once 保证。查询不到可靠回执时保留结果未知、不重放，由原角色根据最新观测重新决策。正常暂停从安全检查点续跑；异常接管还须隔离旧输入链，并沿用累计预算与原时限。详见[异常中断恢复](crash-recovery.zh-CN.md)。

### 有限轨迹中的知识提炼与验证成本

**难点：** 单次成功可能依赖特定状态，失败也可能来自环境。将整条轨迹直接写成规则容易过度泛化；要求每个候选都完整复跑，又会放大学习成本。

**设计：** Learner 提炼有明确适用条件的候选，独立 Skill Reviewer 检查根因、迁移性、冲突、退化风险、简洁性和边际价值，按证据缺口选择探索或普通执行验证。候选、基础版本与验证记录保持绑定，用户复核结果和差异后逐文件确认入库。

**取舍：** 局部知识成立、整任务收益和迁移效果分别记录。整任务失败不抹去独立成立的局部知识，局部有效也不能替代任务收益证明；验证按需选择。学习更新技能文件，不训练模型权重，普通任务结束不会自动启动付费学习。详见[Skills 自进化](skill-evolution.zh-CN.md)。

## 工程支撑

| 支撑模块 | 实现与职责 |
| --- | --- |
| 助手接入与后台托管 | MCP / Control API 提交和控制任务，独立后台持有执行生命周期；客户端断开不终止后台任务。兼容宿主可桥接问答，否则通过 Console 回答。 |
| 模型网关 | 按角色选择模型、适配协议，统一记录请求、响应与提供方返回的用量。 |
| Session 与存储 | SQLite 保存任务状态、版本记录和索引；文件保存对话、图片、UI 树与恢复正文；进程内存维护活跃会话和可重建工作副本。 |
| Console 与只读预览 | 展示实际模型输入输出、工具、观测、回执与事件；预览复用已有画面和模型事件，不增加第二条设备采集或输入通路。 |

## 可观测性与效果评价

可观测记录用于还原一次执行并定位问题；基准评测器独立检查最终任务状态。分析时区分角色调用、模型轮次、工具调用、设备动作，以及任务耗时、模型耗时和 token/cache 用量，缺失用量保持未知，不按零计算。

运行时接受完成结论，仍需结合实际业务证据或外部评分判断效果；只读投屏不参与任务调度，预览故障不改变执行。评测条件与成绩见[评测报告](androidworld-results-20260921.md)，轨迹与指标入口见[Console 指南](observability.zh-CN.md)。
