# GUI 脚本详设

[English](gui-script-design.md) · [架构索引](architecture.zh-CN.md#模块设计文档) · [Skills 自学习](skill-evolution.zh-CN.md) · [命令与示例](../evaluation/gui_scripts.md)

ClickClick 可以把完成的 Android 任务生成带版本的 GUI 脚本。脚本描述一条可复跑的 App 操作路径，每一步都有初始条件、动作和可见结果。同一份脚本可以先用控件树定位，下一步再用截图定位。

```text
勾选录制 → 保留原图和动作回执 → Learner 生成 → Reviewer 独立审查
         → 专用模拟器复验 → 版本登记
回放异常 → 有限接管 → 复核并交还 → 判断是否修订脚本或提炼 Skill 线索
```

## 从任务生成脚本

1. **任务开始前勾选录制。** 「录制脚本」设置 `generate_test_script`，任务照常执行。录制器按观测 ID 保留可用的原始未标注图片，并记录图片尺寸、设备坐标空间、旋转和裁剪。没有原图或观测未被接受时记录原因。普通任务默认关闭这项留存。
2. **用实际轨迹约束每一步。** 勾选录制的任务成功后，后台在一个 Android App 的轨迹中读取已确认派发的动作，以及对应的前后观测。有可用树证据的动作使用语义选择器，坐标点击使用前后原图中的对象证据，轨迹里的 App 启动仍为启动动作。Learner 按实际动作模式和顺序提出选择器、条件和选区，程序根据原始证据核对。存在轨迹缺口或不支持的坐标变换时保留失败原因。
3. **核对树和图片之间的转场。** 如果树上的一个动作打开了纯图页面，下一步的视觉对象在动作后可确认、动作前可确认不存在时，就能用来证明转场。程序还把上一步的结果检查带入下一步前置条件。最终条件需要能区分任务开始和完成。
4. **独立审查并打包。** Reviewer 检查路径、目标、结果和参数绑定。可下载包包含 `script.json` 和引用的图像素材。脚本与素材的哈希用于核对审查版本。生成阶段按独立预算读档案、写草稿，无设备输入。草稿需经设备回放才能登记。

脚本声明 App、版本、参数、初态 `initial` 和终检 `final`。每步包括 `before`、`action` 和 `after`，可带 `blocked_when`、`retry_when` 或 `timeout_seconds`。业务输入使用声明参数。当前自动生成遇到同时包含纯图点击和参数化输入的轨迹会停止，以防图像模板固化录制时使用的输入值。

## 回放时如何定位

| 可用证据 | 执行器如何绑定动作 |
| --- | --- |
| 可操作的控件树 | 每次从当前观测匹配 resource ID、角色、文字和祖先。对重复控件，可以使用唯一相对锚点，或使用有范围约束且位置可区分的顺序。输入时要求同一可编辑控件实际获得焦点。 |
| 树中有多个满足条件的点击候选 | 步骤带有图像证据时，可以用匹配位置缩小到当前树候选。单图块模板可以辅助区分树中的候选。纯图点击需要完整的视觉对象证据。 |
| 仅有截图 | 在当前帧确认对象身份及对象内唯一控件，再把记录的相对触点投影到当前控件边界。 |

### 纯图如何录制

Learner 根据前后原图和实际触点，提出一组可见的行、卡片或面板边界及内部不重叠的区域。身份区域用来区分对象，控件区域必须包含实际触点，结果区域描述同一对象在点击后的变化。还可以标出分隔线等边界，以及需要排除的动态内容。以闹钟为例，可以用名称和设定时间共同认出一行，把「明天」这样的相对日期排除。

程序从原图裁切并遮掉其余区域。录制时核对对象是否唯一、触点是否与真实动作一致、点击后能否确认同一对象，以及结果是不是本来就存在。也能用同初态的额外截图检查选区。自动录制默认用图像区域匹配身份。手写脚本显式配置了文字身份时，可以在回放侧用本地 OCR，仅接受同一容器内唯一且精确的文字匹配。

### 布局变化时如何搜索

纯图回放使用设备原始分辨率截图。默认局部范围以原对象边界为中心，横纵各向外扩展对应边长的一半且至少 12 像素。录制时通常允许扩大到整屏，也可以显式收窄。回放优先核对局部位置，并在允许范围内检查竞争候选。对象整体移动或缩放时，尝试匹配稳定区域的整体布局。内部重排时，从当前图像的可见分隔线或背景块推断行和卡片，再在每个容器内重新定位部件。

每帧中，身份与控件或结果都需要归属于同一个可见对象。两个对象都足够相似、同一对象有多个控件候选，或归属无法确认时，执行器会停在当前步骤等待复查。默认图像相似度阈值是 `0.92`，最小分差是 `0.04`。当第二个对象也达到阈值，即使分差足够也判作歧义。这些数值是匹配参数，程序同时核对对象边界和控件归属。匹配后从当前控件框计算触点，并在真正发出点击前用一张新图复查。

## 等待、动作与接管交还

回放先核对脚本初态，再为每一步轮询新观测，确认局部前置条件后通过现有动作与观测事务派发输入，并等待局部结果。前置条件有一个期限，派发和后置检查共用另一个期限。两者使用同一步的配置，普通步骤默认 12 秒，启动 App 默认 15.5 秒，可按步骤覆盖。显式 `wait` 只等条件成立。命中 `blocked_when` 可提前结束前置等待。最后用新观测核对 App 和终检结果。

普通回放无需模型。显式开启的接管只能选择策略允许的 App 内动作，每个动作都有前后检查以及总时限和动作上限。针对已登记脚本，当前自动接管仅在动作未派发时推导至多一个动作。支持具有稳定控件身份但数字描述变动的定位，以及能验证窗口归属和唯一关闭按钮的 App 内弹窗。纯图异常可走显式接管策略。

接管后的控制权由执行器决定，交还前用新观测再次核对条件。

| 决定 | 所需证据 |
| --- | --- |
| 重试本步一次 | 本步前置条件满足，结果尚未发生，也没有阻塞。原动作必须未派发，或派发结果已知且显式的 `retry_when` 条件成立。 |
| 继续下一步 | 本步后置条件和下一步前置条件同时成立，且下一步没有阻塞。 |
| 结束 | 最终条件和配置的独立结果检查通过。 |
| 停止 | 无法核对到可交还状态。派发结果未知时停止自动输入，可能需要先核清设备状态。 |

## 复验与版本登记

显式回放使用专用 Android 模拟器，校验序列号、AVD 身份和已安装 App build。脚本的初态条件声明需要的界面和数据。如果脚本含启动步骤，它可以打开 App。快照验证会在每轮前将整个 AVD 恢复到指定快照，再核对 build 和初态。Console 的测试设备使用独立 ADB 端口，普通任务设备池不可见。缺少配置或必要输入时，保留可下载的草稿，供显式验证。

| 路径 | 登记需要的证据 |
| --- | --- |
| 初版 | 审查通过的原样草稿，两次从同一初态开始、关闭接管的独立回放。执行器检查终检条件在开始时未满足，在结束时已满足。被动操作和满足条件的树上 Tab 点击可以自动登记，其他已通过的脚本待审批。 |
| 显式修订 | 接管成功且已有原生证据时，Learner 可针对一个失败步骤提出局部修订。保留目标、参数、终检、其他步骤以及失败步骤应达到的结果。Reviewer 检查修订，再从同一快照关闭接管复跑，通过后进入审批。 |
| 自动修订 | 候选还要从原登记场景的快照关闭接管复跑。自动登记仅限能确认为低影响的局部选择器修订，其余已通过的改动待审批。 |

如果只是关闭一次性弹窗，随后原步骤通过，系统记录接管过程并保留现有版本。已确认派发并推动界面变化、随后才发生后置检查超时的点击，只能提供 Skill 线索。需要登记修订时，程序重新核对审查哈希、回放回执和上一版本。已登记的文件按版本号保留，回放时可以选定具体一版。

## 如何用于 Skills 自学习

如果接管发现了可复用的业务路径，比如达到同一结果的已验证快捷入口，Learner 可以保存一条 Skill 线索，关联原生动作和前后观测、App build 与被审查的来源脚本。线索和脚本修订可以独立产生。仅定位变化和清障后原步成功重试的情况会跳过线索。后续显式启动 Skills 自学习时，Learner 可以引用符合条件的原始证据，再验证建议的规则。

Skills 回归使用准备脚本构造测试初态。评测器按用例约定核对目标分支的初态条件，并确认业务目标尚未完成。随后把同样的正式目标交给普通 ClickClick，分别使用基线 Skill 和精确候选运行，再独立核对结果与保护条件。配对回归关注 Skill 对 Agent 决策的影响。详见 [Skills 自学习](skill-evolution.zh-CN.md)和[评价体系详设](evaluation-design.zh-CN.md)。

视觉验证分别记录了 Google Clock 与 Android Files 的真实设备输入，以及独立的截图对比。后者覆盖相似对象、跨卡片误匹配和内部重排，分别统计误点与拒点。也已有树 → 纯图 → 树的任务在专用 Android 环境中完成生成、下载和回放。
