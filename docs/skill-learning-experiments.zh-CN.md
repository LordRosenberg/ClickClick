# Skills 自学习历史实验

[当前详设](skill-evolution.zh-CN.md) · [English](skill-learning-experiments.md)

以下为截至 2026-10-15 的历史实验：样本选择、训练重叠、未恢复项、成本未知及负面结果保持原口径，不代表当前版本的通用成功率。

## 实际例子与证据边界

**Markor：已保存笔记后从文件列表重命名。** Learner 提炼的是“保存完成且剩余目标是重命名时，回列表长按 Rename”，不是固定文件名的点击脚本。原任务候选省 3 动作；更换文件名和内容后，同一正文在原预算内完成了基线未完成的任务。这提供跨输入复用证据，不覆盖所有版本和起点。

**Mastodon：内联语言复选框在同页保存。** 条件是 web Preferences 中 Filter languages 为内联列表且 Save changes 同页；不能把 Back 当成关闭选择器，仍须核对勾选和保存后状态。原候选两次普通任务成功，另一份从空白会话重学的正文也成功并确认同页保存采用。尚未验证换语言组合的收益；不同导航路线也使全部步数差无法归因于这条规则。

**Mastodon：发帖默认语言不等于账户语言。** 源页面解释了 Posting defaults 的作用域，支持一个非显然避坑点。空白重学候选运行成功，但直接走网页、未触发该解释页面，因此此次机制采用和成功归因仍未证实；这次成功也比失败基线更贵。

**Mastodon：自动删帖的例外条件。** 新候选按任务要求区分“只保留”的例外，清除多余例外，滚动检查下方设置并确认保存后的状态。空库来源 36 动作失败，同一目标的候选复跑 28 动作成功，原生动作证实规则被采用。全部 8 步差异不能归因于该规则；这仍是单次同目标验证，未证明跨数据稳定性。本轮原生试验产出一个 Chrome 文件，多应用候选组与局部验收机制另有自动化边界测试，尚无原生多文件组成功案例。完整数据见本轮记录（开发仓库实验记录）。

反例同样保留：文件任务有一次失败转成功但证据不足以准入，Calendar 未恢复目标，高效的 GitHub 来源正确 skip。不能删去这些结果再报告整体成功率。数据与比较口径见阶段验收（开发仓库实验记录）和最新 MobileWorld 记录（开发仓库实验记录）。


## 2026-10-13 量化复验

在冻结的40个筛选 AndroidWorld 任务上，空库官方成功31/40，使用原生生成库后33/40：77.5%→82.5%，增加5个百分点、相对提升6.45%。9个原失败任务恢复4个（44.4%），同时保留2个正常任务失败，净增2个成功；不是全量116题或稳定平均收益。9个原成功且实际激活生成skill的正常任务均通过，但激活不等于因果证明，其他失败仍计入分母。

独立的6题 MobileWorld 目标集为5/6→6/6，83.3%→100%，相对提升20%，恢复1个失败、5个原成功均通过。样本小且与 AndroidWorld 使用不同模型，不能合并或代表全量117题。正常任务动作122→126、请求167→179，没有整体提速证据。

本轮没有达到 AndroidWorld 相对提升15%的目标。两轮保留原普通提示词、harness及官方预算，Jev关闭、不录视频、不发布skills；初始化快照的未知/差异及未计分故障不隐藏。AndroidWorld 的29个前后成功任务动作391→377，请求583→591；不能把全部动作差异归因于生成知识。完整口径与阶段验收（开发仓库实验记录）及逐题数据（开发仓库实验记录）可供复核。

## 2026-10-15 共同库复验与开销修复

同一组选定40题的新空库／共同生成库配对已结清：官方成功29/40→36/40（72.5%→90%），增加17.5个百分点、相对提升24.1%；11个失败恢复7个，原成功转失败0个。六个恢复有具体规则输入与关键操作采用证据，BrowserDraw没有收到生成正文，其恢复单列。完整预算内正常完成为27/40→35/40，保持次要指标；前面的31→33旧成绩不改写，也不混用旧基线。五份生成正文、新独立审查、全40行结果及hash见最新量化报告（开发仓库实验记录）。这是有历史人工成功记录的筛选集合、含训练重叠的学习后复跑，不是全116题、40题未见泛化或稳定因果提升。额外已测初态匹配26/40，14项覆盖未知。

连续探索已接入专用可处置fixture入口。Expense对照中adapter尝试2/8，但多一探针及9次GUI操作使调用78/65、原生时间1368/1052秒；减少初始化不等于总学习更省。针对已观察开销增加同来源分析增量、摘要／claim与单动作交接、候选直接交接宿主强制清理，并修正原生剩余时间及已付费评分只读导出。新增三题学习及源验证共228请求、约43分钟，两个恢复、一个保留有效局部知识但整题未恢复；基线、保护、整批评测和历史发现费用另计。两次固定上下文的比较没有证明稳定降耗。普通提示词、harness及各题上限保持冻结；没有新增案例索引或自动发布。开销诊断与完整账本（开发仓库实验记录）保留全部故障和未知项。

## 2026-10-15 当前闭环与完整冷启动成本

失败研究同时维护两个结论：局部规则是否成立，以及来源任务是否真正完成。局部接纳后，若精确候选的来源复验仍失败，Learner继续沿用同一研究会话和原预算，保留已通过的规则，分析新的阻塞；不会因为一次局部pass直接结束。只有匹配正文、基础库、环境及独立评分的普通执行，才能关闭任务成功目标。无值得继续的可行检查或预算不足时明确退出，保留未恢复状态。

在声明为可处置的专用环境中，连续探针可复用已核对的设备状态；来源改变、待恢复影响或清理边界仍强制重新核验。候选只在独立清理通过后进入审查、普通复验或退出。Reviewer的失败归因区分未送达、未采用、规则无效、其他阻塞和环境故障；Learner比较不同机制及完整执行成本。局部编辑绑定精确基础正文，宿主唯一定位并物化完整文件后审核。上述能力仅属于自学习，普通执行提示词与harness不变。

合入前另修复兼容小窗口的过早拒绝：必需的候选、审查意见和任务事实能放入原请求上限时，回退分配复用自适应历史分页的元数据预留，并继续核验完整序列化交换。未扩大输入上限或删除必要证据。此项修复只有离线回归证据，不改写下面冻结实验的数据。

本次固定40份既有空库轨迹：25份在模型调用前跳过，2份初态覆盖不足，13个目标独立从空库重新学习。学习、探索、审查、清理和普通复验共726次调用、163.97分钟；另有空库控制33次调用，总计759次。每个付费目标平均55.85次调用、12.61分钟，中位12.27分钟、P90为20.62分钟。9个官方失败目标平均15.92分钟，2个成功轨迹提炼目标平均1.80分钟；这是包含未恢复目标的整批成本，不是历史全部研发费用或同一应用持续积累后的稳态成本。

9个可测失败目标有6个源试验官方评分通过，其中5个同时在预算内完整完成；5个中1个在供应商故障后由控制器发起仅审查续接，因此完整原生自动闭环为4/9。另有1个原已官方成功、但运行时未完整结束的目标得到修复。12个目标局部接纳，另1个经故障续接审查；不能把13份正文都计为已证实高价值skill。

对齐同样9题，上轮积累库与本轮冷启动的官方成功均为6/9，完整完成由6/9变为5/9。录音命名、合并笔记本轮未恢复；新增一个菜谱去重完整恢复，另一个仅官方评分通过。两轮协议不同，不能据此认定代码退化；本轮也未完整复现已有库效果。新候选尚未组合为共同库或完成正常任务回归矩阵，因此不生成新的40题或全116题成功率。

本轮观察到13个Learner会话、1次压缩；配置为history_tokens=80,000、max_input_tokens=100,000。已返回usage的输入小计15,537,353token，缓存读取1,458,304；220个调用usage未知，金额未知。缺失usage保持未知，不作为零成本。以上[公开逐题汇总](assets/skill-learning-results-20261015.json)不含凭据、设备画面或本机文件路径；完整原生回执和实验skills保存在开发仓库的OpenSpec实验记录中。

## 实现入口

2026-10-14 四小时压力验证没有补出稳定任务恢复的新证据。费用规则能提炼详情读取和误触删除确认等局部知识，并在接纳后继续探索，但源任务仍失败；录音旧正文虽有源与换名成功，后续原生取证发现app报告的双后缀问题，修订正文局部通过但源复验失败。不能用旧成功为修订版背书。该轮修复了学习格式、预算内传输重试、原生证据衔接及旧输入投影限制；离线通过不代表成功率提升。完整验收记录（开发仓库实验记录）保留反证、环境中断、未恢复目标与成本。

2026-10-14 的实现增强了三个环节：Reviewer 用原生证据区分未送达、未采用、规则无效与后续障碍；Learner 在已有恢复选项中比较不同机制并记录选择、实际探测结果和成本；已有文件及当前隔离草稿支持绑定精确基础版本的局部编辑，由宿主生成完整正文再审核。仍使用同一 Learner＋Reviewer 和共享预算，没有必跑矩阵，也没有新增案例索引或自动发布。候选/说明去重精简以保持原上下文上限。框架测试不代表新增成功率收益，前述量化结果保持原口径。
