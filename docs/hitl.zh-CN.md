# HITL：提问、确认与执行中调整任务

[首页](../README.zh-CN.md) · [English](hitl.md) · [机制与宿主协议](hitl-design.zh-CN.md)

在 Console「设置 → 运行与学习」开启「必要时向我提问或确认（HITL）」。助手引导首次安装默认开启，其他安装默认关闭；已有保存选择优先。设置影响新任务，既有任务保留创建时的开关，连接 MCP 不自动修改它。

## 回答体验

Planner/Executor 在缺少必要信息、重要选择或授权时提问，先使用任务描述、已有回答和可读取证据，已有明确授权不重复索取。密码、验证码和支付凭据使用 App 自身安全流程。提问必要性由模型判断，并不保证从不漏问。

任务等待时不调用模型或操作手机，原期限继续有效。Console 显示持续的待答入口：可选择或自由回答，选项不自动提交；确认使用明确允许／拒绝按钮。「稍后回答」只关闭弹窗，「无法回答」与「取消任务」分别处理。一次可包含 1–3 个澄清问题，完整提交后续接原角色会话，动作前重新观察。

有效的助手回复桥接／前台 CLI 可在原入口回答，否则使用 Console。入口断开或未及时呈现时转到 Console，已呈现且连接有效不会因思考超过 30 秒而转移；Console 可显式接管。托盘通知只打开任务页，不另建回答表单。默认最多 8 次提问，每次最多 1800 秒，单答最多 4096 字符，任务更早时限优先。

## CLI

```powershell
python -m agent.main --hitl "你的任务"
python -m agent.main --hitl --answers console "你的任务"
```

HITL CLI 使用同一 Control API、任务库和回答 broker。交互终端允许编号或自由回答，确认必须明确输入 yes/no；`?` 表示无法回答，`cancel` 取消，空输入不表示同意。非交互、EOF／退出或显式 Console 模式转到 Console 并给出任务 URL。关闭 HITL 时继续使用原 standalone CLI 路径。

## 主动调整正在执行的任务

在助手中补充新要求即可通过 `steer_task` 追加到原任务，无需先暂停或等待提问。

- 运行中区分“已收到”与“计划已更新”；Planner 保留有效阶段或修订受影响工作，过时模型响应不能继续派发。
- 已派发动作先保存真实结果；发送、预订等效果不会自动撤销。
- 暂停任务仍暂停；等待中的旧问题与续接资格重新核对。
- 完成后创建关联后续任务，保留原完成记录；关闭 HITL 的既有任务需为新任务开启能力。

原需求与后续修改按序保留，有效约束、授权和累计消耗不清零。助手接入见[MCP 指南](local-mcp.zh-CN.md)，并发顺序见[HITL 详设](hitl-design.zh-CN.md#用户变更与在途动作的顺序)。

## 投屏与任务进度

派发后可打开任务投屏页，同时查看手机最近画面和返回的模型正文／思考摘要；工具参数在本轮完成后展示。预览与任务详情可互相跳转。只读预览复用本机 Android 任务已有画面，暂停、结束或缺帧时说明状态，不影响任务继续执行。详见[Console 指南](observability.zh-CN.md#任务投屏预览)。

## 预算耗尽后的续跑

普通默认累计上限为 200 次 Executor 决策、1000 次模型请求。耗尽保持失败；有安全预算检查点时可明确增额后继续，保留原失败与累计消耗。修改要求不重置预算或自动延长期限，评测不自动续跑或覆盖原成绩。干净暂停与异常接管的差异见[恢复详设](crash-recovery.zh-CN.md#干净暂停预算续跑与异常接管)。
