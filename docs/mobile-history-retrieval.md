# 历史检索、笔记与上下文压缩

持久 Session 保存历史证据，Harness 按当前任务选择检索范围并管理上下文压缩。本文说明存储身份、读取接口和压缩边界。两种角色配置共用这些机制。

## 数据来源与身份

- 阶段：程序在阶段实际被观察时记录 revision-qualified ID、Planner 当时的完整目标、目标应用、首次/最近出现步骤。修订计划产生新 ID，旧目标保留；未执行的计划尾部不冒充已发生的阶段。
- 观察：截图、界面文字、首次记录步骤和每次复用时的 `(step, stage_id)`。复用同一观察不会伪装成再次采集；步骤和阶段过滤必须匹配同一次出现。
- 事件：Executor 当步报告、提交动作与程序回执分别保存。来源同时关联动作依据帧和回执的结果帧。派发成功不等于业务成功。
- 笔记：Executor 写正文和明确的观察来源，程序添加写入步骤/阶段与版本。追加保留重复值和来源；替换产生新版本。写入时间不是正文事实发生时间。
- 对话：每个存储片段有独立 ID、执行步骤和原文文件引用。相同文本可以共享文件内容，但不会共享片段身份。

所有查询按任务隔离。历史截图不可作为当前动作的坐标依据。文字搜索只能找已有文字，不能检索尚未被描述的图像内容，也不推断同义词或事实。

## 默认输入与预算

Planner/Reviewer 接收当前观察、任务/计划/反馈、已有早期摘要和完整事件尾部、预算内笔记正文。
补充的阶段目录最多显示最近 3 项，内容预算 2,400 字符；笔记目录也有 2,400 字符预算，最多 12 项。
笔记目录只给键、版本、标题、短预览、最近两个来源以及省略来源数量。完整来源随笔记正文读取。
目录不足会标明总数或省略数量，并提供后续分页位置，不要求模型为了“补齐目录”主动阅读。

操作摘要保留原有 12,000 字符预算，笔记正文保留单独 12,000 字符预算。
这些是内容字符预算，不是 token 数，也不包括角色提示词、当前截图和 JSON 包装等整个请求成本。
Executor 使用连续对话与有界笔记目录；不重复注入 Planner/Reviewer 的事件包和阶段目录。

## 定位顺序

先判断当前观察、已有完整摘要和笔记是否已经足够。只有影响决策的具体缺口才读取。

1. 有笔记键或观察 ID：直接 `read_note` / `read_observation`。
2. 不知道笔记键：`list_notes({"query":"标题"})`，字面匹配键、标题或正文，返回匹配附近的短预览和键。
3. 知道历史目标，不知道 ID：`list_stages({"query":"收集标题"})`，返回目标预览、真实 ID、出现步骤范围；完整目标保存在原始记录中，超长预览标记 `goal_truncated`。
4. 不知道阶段：`list_history({"query":"标题"})`，在当前任务的观察文字、关联操作报告及阶段目标中做不区分大小写的字面匹配。
5. 已知 ID/范围：将返回的 `stage_id` 或步骤范围用于 `list_history`，再读取相关观察。

`list_history({})` 默认当前阶段；带 `query` 或步骤范围时默认整个任务。
显式 `scope` 覆盖默认，显式 `stage_id` 优先于 scope。返回结果回显实际过滤条件。
阶段/笔记目录按最近记录优先；观察目录按首次记录顺序分页。
分页使用返回的 `next_offset`，不是模型猜页码。查询默认最多 8 项、单页条目内容预算 6,000 字符。
预览标注来源，可能有省略号；涉及被省略内容时读正文，不能把裁剪预览当作完整记录。

例如当前在 `plan_3_stage_1`，但要查旧阶段的标题：

```text
list_notes({"query":"首条标题"})
→ note_key=first_title, version=2, observation_ids=[obs_a]
read_note({"note_key":"first_title"})
→ 完整正文和全部来源；如已足够，停止查询
read_observation({"observation_id":"obs_a","view":"image"})
→ 只有确需核对原图时才读取
```

若笔记没有记录该内容，可直接按已知文字搜索历史，不需要先猜它属于第几版计划。
历史文字/图片读取只附简短事件索引，不重复附大段事件正文；完整动作与回执通过同一观察的 `view="events"` 分页读取。
模型仍负责判断信息是否足够，不新增强制“阅读理由”工具调用或语义拦截。

## 压缩边界由程序决定

程序按执行步骤归组对话片段，保留最近两个步骤的全部片段（包括决定和回执），只选择更旧步骤进入压缩请求。
压缩模型收到“已有摘要＋被选中的旧对话”，看不到保留的近期对话，也无权修改其存储内容。
例如步骤 1～6，每步分别保存决定和回执：

```text
压缩输入：旧摘要 ＋ 步骤 1～4 的全部片段
保留原文：步骤 5～6 的全部片段
恢复输入：新摘要 ＋ 步骤 5～6 原文 ＋ 当前观察/运行状态
继续执行：在后面追加步骤 7、8……
```

不足三个不同执行步骤时不进行这类压缩。后续压缩用旧摘要与新选中的旧步骤生成替代摘要，不无限累加摘要。
记录保留/压缩的片段 ID 和步骤供审计；原文与笔记仍然保留。
模型仍可能遗漏被允许压缩的旧信息，但它不能把保留区的原始对话改成摘要。

## 阶段与笔记接口

每个计划只有一个当前阶段；`assumption_roadmap` 是待验证的未来设想，不生成可执行阶段。阶段完成后回到 Planner，未来设想不会自动激活。所有面向模型的笔记读写、目录和回执统一使用 `note_key`，与 `stage_id` 区分。

## 验证范围

181 项相关离线测试通过，覆盖运行时、执行器、调度、会话、取消、结构和持久化。新增检查直接检查压缩请求与保留原文，验证跨阶段复用帧、动作前后来源、笔记旧版本、目录预算和分页完整性。这些检查验证存储与输入构造行为，不直接证明真机成功率、模型查询次数或总 token 的变化。
