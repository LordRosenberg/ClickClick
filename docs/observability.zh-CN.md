# Agent 可观测性与效果分析

[English](observability.md) · [中文首页](../README.zh-CN.md) · [部署](deployment.zh-CN.md) · [任务实例](task-examples.zh-CN.md)

可观测性覆盖每个 ClickClick 任务，包括自定义应用工作流。它将模型收到和返回的内容与后续工具、设备操作及观测关联起来。AndroidWorld 等基准提供外部正确性检查，不是这些记录能力的来源。

## 从执行到 Console

1. 运行时和模型网关生成角色调用、模型轮次、工具、动作及观测记录，通过稳定引用关联任务与对应调用或动作位置。
2. `TraceWriter`、任务存储和共享存储保留事件、版本化记录及产物引用。大型请求／响应正文和图片可独立于精简时间线加载。
3. `ObservabilityQueries` 构建任务摘要和调用时间线。SSE 传送已存储及后续实时事件，产物接口提供引用内容。
4. Console 展示规范化角色调用及其中的模型／工具轮次。选中调用时展示其决策与观测，不借用同一设备动作位置上其他角色的内容。

来源：[轨迹写入](../agent/traces.py)、[任务存储](../agent/revisable/store.py)、[查询与指标](../control_api/services.py)、[API 与 SSE](../control_api/main.py)、[调用展示](../web/src/components/AgentCallsBlock.tsx)、[所选调用检查](../web/src/components/StepInspector.tsx)。

## 检查一次运行

打开任务的 **Timeline**，选中角色调用，展开输入、输出与工具记录。归因于模型前，核对实际提供的指令、上下文和返回决策。只能查看提供方返回的输出或推理摘要，不能重建隐藏的内部推理。

检查 **active skills** 中实际交付的 ID 和版本。比较某次调用看到了什么时，打开观测并选择相应对话图片。镜像的 **Frame** 模式展示所选历史视觉证据，**Live** 展示当前设备；两者回答不同问题，不能当作同时采集的状态比较。

通过 **Trace 流** 查看错误、取消和诊断事件。并非所有采集／压缩字段都有独立图表，更深入的检查需要关联产物或离线查询。任务标为 **运行时完成** 表示运行时接受了完成决策，不能独立证明每个业务字段正确。

## 指标含义

| 指标 | 解释 |
| --- | --- |
| 任务执行耗时 | Console 中的运行时任务时长。基准 worker 耗时可包含预检／清理，边界不同。 |
| 角色调用耗时 | 所选完整调用的耗时，包含模型推理之外的工作。 |
| LLM 耗时 | 已记录的模型轮次延迟，并在可用时聚合，不是完整任务墙钟时间。 |
| Input / cached / output | 归一化的提供方用量。缓存信息可能缺失，未知不等于零。 |
| 角色调用／模型轮次／工具调用／设备动作 | 不同计量单位。一次角色调用可含多个模型轮次和工具，复合输入可含多个等效设备动作。 |
| 压缩、图片和文本估算 | 用于从记录／离线分析中定位上下文开销，不一定等于提供方计费 token。 |
| 采集来源与降级 | 区分 scrcpy、回退证据和相关故障。持久观测不一定枚举每次内部采集。 |

账单不可用时，提供方调用数和输入量可帮助比较资源需求。金额比较还需要实际用量、价格，以及一致的缓存和重试计量方式；未知字段保持不可用，不编造数值。

## 分析失败或高开销运行

| 现象 | 检查方法 |
| --- | --- |
| 字段或值错误 | 对比源指令／笔记、提交动作、焦点／回显结果和应用保存状态。回显正确也可能只是成功输入了模型抄错的值。 |
| 重复点击或滚动 | 比较观测 ID、目标和结果内容。相同坐标可能操作不同记录或显示新行。 |
| 重复重规划／审核 | 检查阶段变化和每次调用可用证据，判断是否出现新事实，还是重复同一问题。 |
| 历史开销高 | 检查实际请求各部分、历史检索、图片发送和压缩事件。摘要变短不自动意味着总调用或成本下降。 |
| 页面与动作不匹配 | 在 Frame 中查看模型当时收到的截图，对照操作目标和执行结果，再到 Trace 流检查是否有采集失败或重试。Live 展示的是当前屏幕，不能用来还原当时的画面。 |

通用方法是区分模型选择、工具校验、实际派发、观测效果和保存的任务结果。这能支持诊断，但不会自动分类所有错误，也不直接证明因果解释。

采集变慢时，应查看包含等待和重试的完整耗时。需要进一步排查画面与控件不一致、采集超时等问题时，可参考[采集诊断字段说明](scrcpy-observation.md#capture-diagnostic-fields)。

## 程序化访问

API 运行期间，将以下只读请求中的 `TASK_ID` 替换为目标任务：

```bash
curl http://127.0.0.1:8080/api/tasks/TASK_ID/timeline
curl -N http://127.0.0.1:8080/api/tasks/TASK_ID/stream
```

Windows PowerShell 使用 `curl.exe`。记录返回的产物引用可通过 `/api/artifacts/{ref}` 访问。任务记录可能包含指令、应用内容和截图，分享前应选择合适产物或脱敏。

检查应用正确性时，应查看最终应用数据或使用外部验证器。[AndroidWorld 评测](evaluation.zh-CN.md)是其中一种集成，其冻结 fixture 与评分独立于普通 Console 任务。
