# 设计决策与取舍

[首页](../README.zh-CN.md) · [English](design-decisions.md) · [架构](architecture.zh-CN.md) · [技术概览](reliability-design.zh-CN.md)

ClickClick 将语义选择交给模型，将机械校验交给 Harness。以下设计说明这种分工如何影响可靠性、延迟和扩展方式。

## 角色策略

**默认 Planner + Executor，Reviewer 按需介入。** Planner 管理阶段目标，Executor 管理局部操作。两个角色均可针对具体冲突请求独立审核，也可通过 `plan_reviewer` 配置强制最终审核。

普通执行已经不断产生观测和反馈，每个阶段都审核会增加调用，却未必补充有效证据。[配对任务实验](runtime-study.md)未发现强制审核的稳定准确率优势，因此采用较简单的默认循环。按需审核依赖模型判断；运行时拒绝状态未变的重复审核，限制无效循环。

<a id="context-budget"></a>
## 上下文预算

**Executor 历史阈值默认为估算 16,000 tokens。** 这是触发历史压缩的软阈值，区别于模型窗口和完整请求大小。

压缩按完整执行步骤分组，保留最近两个完整步骤。结构化摘要区分结果、决策／尝试与关键上下文，并逐条关联来源。原始产物和笔记版本留在 Session；版本化短保留笔记、当前状态与未解决问题独立于摘要恢复。笔记版本与短正文完整匹配时允许可逆展示去重，省略不删除原始记录。参见[记忆与上下文](memory-and-context.zh-CN.md)。

四组匹配的有效任务中，将阈值提高到 24k 后，压缩调用从 19 次降至 12 次，worker 时间降低 8.1%；总模型调用仍为 146 次，累计文本输入估算增加 17.3%。这一取舍支持保守默认值，具体条件和局限见[实验报告](runtime-study.md)。

可在模型的现有配置中覆盖阈值：

```json
"context": {
  "executor": {"history_tokens": 24000}
}
```

`context.max_input_tokens` 可额外限制完整请求的估算输入量。图片估算可能与提供方计量不同。

## Prompt cache 连续性

历史消息和图片在活动预算内保持稳定。频繁重写前缀可能减少名义输入量，却损失可复用缓存。历史仍受压缩阈值约束；优化时综合衡量未缓存输入、缓存输入、输出和额外调用。

<a id="scrcpycollector-与-python"></a>
## scrcpy、Collector 与 Python

**scrcpy 提供画面，Collector 提供结构，ADB 提供回退画面。** scrcpy 视频流专用于任务观测，Console 查看任务已保存的截图；无障碍数据补充索引控件、窗口和交互证据。

采集检查请求新鲜度与窗口状态，并采用有界静默区间和重采。普通内容更新只作为诊断，不自动触发新的树遍历，使动态页面仍然可被观察。窗口检查通过时，缺树也可交付可用画面。

`snapshot` 查看当前状态，`sequence` 查看时间变化，`detail` 获取新鲜原生帧，提供指定裁剪或四块重叠阅读分片。细节附件保留观测身份和原生几何，动作仍引用新鲜全局画面。`sleep` 等待录音时长等必要时间，下一次决策再获得新观测。已验证的解码环境为 Python 3.12 与 PyAV 14.0.1，部署和诊断见[Collector 指南](accessibility-collector-setup.zh-CN.md)。

## 定向文本替换

**只有支持且可识别的字段才合并聚焦与替换。** 模型提交目标和文本，Harness 建立焦点、验证字段身份、清空和输入，并检查读回。歧义字段、密码字段及不支持的控件不使用相同路径。

这一方式减少模型往返，并保留输入反馈。部分执行会说明哪些操作已经发生。读回确认字段值，应用是否保存仍需要独立证据。

## 原生节点绑定

支持的本地索引点击保留被观察 Android 节点的引用，在有界刷新和身份检查后执行一次原生动作。节点移动后可继续作用于原对象，避免旧坐标指向其他控件；失效或不确定结果不自动重试或回退到坐标。

该路径依赖兼容 Collector 和进程内 Driver。坐标动作、复合动作辅助点击及不支持的传输保留原路径。[原生节点技术报告](native-node-click-20260920.md)说明具体检查和设备验证。

## 按角色交付 skills

**应用 core、workflow 和通用知识分别维护。** 设备 profile 与阶段选择确定适用内容，显式角色分区决定交付范围，ID、版本和内容检查使实际交付可追查。

支持的应用技能可以授权闭集复合动作。详情读取后返回的操作保留中间证据，以返回后的页面作为动作依据。这减少重复交接，但扩展了动作空间，因此提交动作和物理子动作分别计数。接口不接受任意脚本或模型生成的动作序列。参见[技能编写](../skills/README.zh-CN.md)。

多应用学习按知识所属应用拆分文件，在同一冻结 overlay 中选择必要验证；局部有效性逐文件审查，整任务失败不否定独立成立的知识，依赖失败和已知退化则阻断受影响候选。批准时重查精确正文、基础库与运行合同，完整记录按来源回查，避免反复传入同一评审。见 [Skills 自进化](skill-evolution.zh-CN.md)。

## 预算与指标

普通任务的限制由调用方提供。AndroidWorld 实验使用按复杂度计算的动作和模型调用上限，以及 900 秒截止时间。压缩计入模型调用，非动作阶段交接不计入设备动作。

耗时、提供方调用、提交动作、物理子动作和 token/cache 用量分别报告。[评测报告](androidworld-results-20260921.md)定义基准使用的动作空间。缺失的提供方用量保持未知，估算输入量不直接作为金额。
