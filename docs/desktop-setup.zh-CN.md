# ClickClick 桌面安装与连接

## 安装包包含什么

下载适合你电脑的安装包：Windows 使用 `.exe`，macOS 根据芯片选择 Apple Silicon 或 Intel 版本。安装包已包含 Python、运行依赖、Console、技能和手机连接工具，不需要另装 Python、Node 或 Git，也不需要手动安装依赖。

任务记录使用内置 SQLite 数据库，首次启动自动创建，无需安装数据库服务。Jev 摘要检查默认关闭，需要时可在设置页启用并配置 API。使用时需要浏览器、模型服务的网络连接，以及手机调试授权；Windows 通过 USB 连接部分手机时可能需要厂商驱动，Wi-Fi 连接不需要 USB 驱动。

你的模型配置、任务记录、截图和技能保存在所选安装目录的 `data/` 中，升级时会保留。备份时请妥善保管该目录，其中可能包含账号凭据和应用内容。第三方组件的许可证可在安装包的许可证目录中查看。

请从[官方 Releases](https://github.com/LordRosenberg/ClickClick/releases) 下载安装器；GitHub 的 “Source code” 压缩包用于源码部署。如果没有适合你系统的安装器，可使用[源码部署指南](deployment.zh-CN.md)。macOS 测试包可能触发系统的来源检查，请核对下载来源并遵循系统提示。

## 两种首次安装入口

1. **让助手安装（推荐）**：把下面的提示词发给能执行本机命令的助手，由它下载、校验、安装并指导连接；按助手提示确认必要的文件和命令权限。
2. **自己安装**：下载适合你电脑的官方安装器，运行后会自动打开本机设置页，按页面完成模型配置和手机连接。

> 请帮我在这台电脑上安装并连接 ClickClick（https://github.com/LordRosenberg/ClickClick）。按安装指南识别 Windows/macOS 和 CPU 架构，从官方 Releases 下载匹配的安装器并核对该发布的 SHA-256；没有匹配安装器时，按源码部署指南处理，不把源码压缩包当安装器。安装后检查退出状态及后台 identity。打开本机设置页，让我选择订阅登录或 API，协助官方授权；API Key 由我在页面填写，不放进聊天。问我用 Wi-Fi、USB 还是已有模拟器，代办电脑侧连接并具体指导手机调试与权限确认。在设置页的“让助手添加”入口取得包含完整本机配置文件路径的接入提示词，读取该 stdio 配置，并用你自己的官方 MCP 管理命令或配置入口注册 clickclick，保留已有设置。若通过安装版 CLI 导出，必须指定 --client generic --transport stdio --output 和一个明确的本机文件完整路径，再读取该文件；不要调用 ClickClick register 代替你的注册步骤。能在当前会话加载 MCP 就调用 get_status，检查模型配置和手机初始化，分享 Console 链接。若需我重启客户端或新开会话，请报告“注册完成，待验证”，给出具体操作，并让我在新会话发送：“请调用 ClickClick 的 get_status，检查连接、模型配置和手机初始化，说明是否就绪及未完成事项。”不要把注册或 ADB 在线当成验证成功；get_status 不进行模型请求或手机任务测试。只有我明确要求时才执行实际手机测试任务。

通过命令行安装时，`--unattended` 可关闭自动打开浏览器；`--no-start` 可只安装文件，稍后再启动 ClickClick。

## 本机目录与后台

首次双击安装可选择磁盘和目录，程序会放入所选目录下的 `ClickClick` 文件夹；后续安装自动沿用已记录的位置。无人值守首次安装默认使用 Windows `%LOCALAPPDATA%\ClickClick` 或 macOS `~/Library/Application Support/ClickClick`，可用 `--home "<所选安装目录>"`指定其他位置。默认用户目录仅保存很小的安装位置记录；Python、依赖和任务数据都放在选定目录。安装目录所在磁盘不可用时会报错，避免在其他位置重复安装。

- `versions/<版本>/`：应用、私有 Python、依赖和设备资产。升级成功后清理旧程序；仍被助手会话占用的旧 MCP 运行环境会在连接释放后清理。
- `data/`：任务数据库/截图、私有模型配置与订阅凭据、MCP 凭据、用户技能及日志；升级保留。首次将运行技能复制到 `data/skills/`，后续升级只补充缺失文件，保留用户修改。
- `bin/clickclick.cmd`（Windows）或 `bin/clickclick`（macOS）：稳定命令入口。
- `current.json`：当前版本指针。

升级会关闭旧托盘和后台，更新桌面入口，并在新版启动成功后清理旧程序。新版启动失败时会尝试恢复旧版本。使用设置页提供的 MCP 配置，升级后无需修改助手连接。安装到另一个 `--home` 目录会创建独立安装，原目录的数据仍保留。

后台随当前用户启动，只监听本机地址 `127.0.0.1`。执行手机任务时，请保持电脑、ClickClick 和手机在线；电脑关机、休眠或无线断连会中断执行。

安装后可让助手使用 CLI 的 `status`、`start`、`stop`、`restart`、`setup` 管理后台。重启或停止前，请先完成、暂停或取消任务。遇到启动失败，可查看 `data/service.log`；如果系统策略禁止后台启动，安装器会显示错误，已安装文件会保留。

## 模型接入与核心设置

打开 Console 的“设置”，选择 **Codex / ChatGPT 订阅登录** 或 **配置 API**：

- 订阅：填写账号可用的 `chatgpt/<模型ID>`，点击“登录并授权”。设备授权码显示在 ClickClick 设置页，可点击“复制设备授权码”，再粘贴到自动打开的 OpenAI 授权页并确认；ClickClick 自动等待完成并保存本机授权，后续可以复用。
- API：填写带服务商前缀的模型 ID、API 地址和 Key。HTTP User-Agent 可选；高级参数可配置 reasoning 强度/摘要、流式响应、输出/上下文长度，以及服务商文档规定的 thinking 等额外 JSON 参数。已保存的 Key 和额外参数不回显，留空保留，输入 `{}` 清除额外参数。

模型需支持图片与工具调用。各角色可跟随默认模型或单独选择。Console 与 MCP 任务使用同一模型配置和 ClickClick 自己的 harness，不会自动继承助手的授权或聊天上下文。

Jev 摘要检查默认关闭；可在设置页开启并配置独立的 API 地址、Key、模型 ID，以及高级模式、超时和服务异常处理。开启后摘要及相关文字证据会发送给 Jev API，产生额外请求；保存不会测试服务。Key 不回显，留空保留，改 API 地址需重新填写。Jev 配置与主模型的 API/订阅选择独立，重启后保留。

设置页还可调整任务与 Skill 学习的请求、动作和时间上限，以及本地任务统计与报告导出。修改模型和运行设置前，请先结束所有任务及工作流优化，暂停的任务也需完成或取消。保存后设置立即生效，重启仍保留。学习预算只设置上限，工作流优化需单独启动并授权。任务时限从创建时计算，暂停不会延长。

配置保存在本机 `data/console-settings.json`，无需手动修改文件。保存不会发起模型请求；你可以通过实际任务检查配置是否可用。执行任务时，指令、截图和相关上下文会发送给你选择的模型服务。

## Wi-Fi 连接真机

Android 11+ 无线调试不需要数据线：

1. 手机与电脑连接同一 Wi-Fi，确保网络允许设备互通。
2. 手机开启开发者选项，进入“无线调试”，允许当前网络。
3. 打开“使用配对码配对设备”，在本机配置页填写该页面的 IP、配对端口和六位配对码，点击配对。配对码不存档。
4. 返回无线调试主页面，用这里的 IP/连接端口连接。**配对端口与连接端口通常不同**，不要写死 5555。ADB 自动发现已连接设备时，也可直接检查设备。
5. 检查 `device` 状态，然后让助手调用 `get_status` 查看 Collector/输入法初始化与待人工确认事项。配对成功、ADB 在线与环境就绪是三个不同状态。

网络变化、重启或关闭无线调试后可能需要重新连接；配对码失效时重新打开配对页面。Android 10 及以下通常需要先通过 USB 授权，再执行 `adb tcpip <端口>`，拔线后使用 `adb connect <实际IP>:<端口>` 连接。

## USB 与模拟器

USB：开启 USB 调试，使用数据线，解锁并接受此电脑授权；`unauthorized` 表示等待手机确认，`offline` 时请检查数据线和设备连接。Windows 连接部分品牌手机时，需要安装对应的 USB 驱动。

模拟器：先安装并启动你使用的 Android 8+/API 26 或更高版本模拟器。若设备列表未自动显示它，使用模拟器提供的实际 ADB 地址连接。

Collector、输入法 APK 由安装包提供，后台对在线空闲设备进行初始化。Android/OEM 要求受限设置、安装或无障碍确认时，用户需在手机上完成，助手根据返回的环境步骤给出指引。不要绕过锁屏或企业设备管理策略。

## MCP 注册

HTTP 和 stdio 提供相同的八个任务工具。HTTP MCP 通常使用 `http://127.0.0.1:18081/mcp/`，可通过 `export --transport http` 导出实际地址和本机认证信息；Console 通常使用 18080 端口。托盘统一管理后台与 HTTP MCP，无需分别启动。

设置页提供两种添加方式，默认使用 stdio：

- **让助手添加（推荐）**：页面生成本机 `data/mcp-connection-stdio.json`，复制的提示词包含该文件的完整路径。助手读取配置，通过自身官方 MCP 管理命令或配置入口注册。需要助手具备本机命令执行和文件访问能力。
- **手动添加**：选择助手，复制页面填好路径和参数的注册命令；没有命令入口的客户端按页面给出的配置路径和内容合并，保留其他设置。Windows 命令在 PowerShell 执行，macOS 在终端执行。

页面生成接入文件，由你或助手完成注册。已有同名服务时，请先核对配置。需要 HTTP 接入时，可通过安装版 CLI `export --client generic --transport http --output <完整本机文件路径>` 导出；文件含认证信息，请保留在本机。

注册后，助手能够在当前会话加载 MCP 就调用 `get_status`；否则报告“注册完成，待验证”，具体指导重启客户端或新开会话，再发送页面提供的独立指令：

> 请调用 ClickClick 的 get_status，检查 MCP 连接、模型配置和手机初始化状态，说明是否可以执行手机任务及尚未完成的步骤。不要发起模型请求或手机测试任务。

`get_status` 不发起计费模型测试；实际手机任务需用户明确要求。连接成功后让助手分享 `console_url`，可查看保存截图、步骤、模型 I/O 和日志。

## 启动、关闭和开机启动

安装后双击桌面或开始菜单中的 **ClickClick**（macOS 在用户“应用程序”目录打开），即可启动后台并显示托盘图标。Windows 右键通知区图标打开菜单；图标可能收在任务栏的向上箭头里。macOS 点击菜单栏图标。

菜单提供“打开控制台”“启动后台”“停止后台”“开机自动启动”和“退出 ClickClick（同时停止后台）”。状态显示已停止、运行中、正在执行任务或异常。关闭浏览器不会停止后台；停止后台后托盘保留，方便再次启动。退出后可通过桌面/应用程序入口重新打开。

有任务运行时，关闭操作会列出任务，并让你选择先暂停、先取消或返回。选择暂停后，ClickClick 会保存进度再关闭，下次启动后可在控制台恢复；取消会结束任务。如果暂停未完成，后台会继续运行，并提示你检查任务状态。

“开机自动启动”控制用户登录时是否自动启动后台和托盘，默认开启；关闭此选项不影响当前任务。重新安装和升级会保留选项。CLI `clickclick start/stop/restart/status` 仍可使用，`clickclick tray` 可打开管理入口。异常说明和 `data/tray.log`、`data/service.log` 可用于排查。

## 版本检查与升级

在 Console 的“设置 → 版本更新”查看版本和升级信息。ClickClick 默认在启动时检查，并每隔 12 小时再次检查官方稳定版；你可以关闭自动检查，也可以随时点击“检查更新”。源码部署请通过 Git 更新代码。

发现新版后，Console 任务/设备等页面顶部显示新版提示，点击进入设置页查看版本与发布说明，再点击“确认升级至 <版本>”。页面关闭时后台仍可检查，下次打开会显示缓存结果；不会主动弹出浏览器或自动安装。网络/发布清单错误会显示，检查只访问公开发布元数据，不发送任务、截图、模型密钥，也不发起模型调用。

确认后独立更新器下载并校验官方安装包，随后重启后台。请先完成、暂停或取消活动手机任务；下载期间出现的新任务也会在安装前拦截升级。升级阶段暂不接受新任务/恢复任务，不自动取消或恢复手机操作。API 配置、MCP 凭据、任务历史和用户技能保留。

已安装 CLI 提供：

```text
clickclick check-update
clickclick update --version 0.2.0 --yes
clickclick update-recover --yes
```

`0.2.0` 只是命令示例，必须换成检查返回的版本。请先向用户展示目标版本并取得升级意愿，再执行 `--yes`。助手无需新 MCP 工具，可调用本机 CLI 或指导用户打开设置页。

设置页显示下载、升级、成功/失败状态，后台重启后自动重连。新版本启动失败时尝试恢复旧程序，不回滚用户数据库。异常中断后，确认更新器/安装器已退出，再使用设置页“确认恢复更新状态”或 CLI 恢复任务接收；仍在运行会拒绝恢复。持续无法连接时查看 `data/update-worker.log`、`data/service.log` 和 `current.json`，也可重新运行已知可用的安装器；恢复入口本身不修复程序或启动服务。

升级提示只针对正式发布的稳定版本，Actions 测试包和预览版不触发稳定版提示。如果你的版本没有更新入口，请重新运行最新安装器。macOS 升级受系统安全检查约束；未通过检查时会停止更新并显示原因。
